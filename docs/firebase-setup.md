# Firebase для тренажёра

**Проект:** `dana-schet`, тариф Spark (бесплатный), регион `eur3`.
**Консоль:** https://console.firebase.google.com/project/dana-schet/firestore

## Правила доступа

```
rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /teams/{teamId}/{document=**} {
      allow read, write: if teamId.size() >= 20;
    }
  }
}
```

Писать можно только в команду, чей идентификатор не короче 20 символов.
Идентификатор случайный, лежит в `index.html` в константе `TEAM` — он и есть
пароль семьи.

**Что это значит на практике.** `apiKey` Firebase не секрет: он лишь говорит,
в какой проект писать. Настоящая защита — `TEAM`. Кто узнает его, сможет
читать и портить данные. Личных сведений в базе нет, только примеры по
арифметике и счётчики, поэтому такой защиты достаточно.

## Структура данных

```
teams/<TEAM>/
  players/dana      профиль Даны: уровни, ошибки, монеты, достижения
  players/papa      профиль папы — отдельно, не смешивается
  sessions/<id>     все заходы обоих, с полем who
  team/days         по каждой дате: выполнил ли норму каждый из двоих
```

`team/days` хранит только «да/нет» по датам — этого хватает для командного
зачёта и не раскрывает подробностей занятий.

## Если синхронизация перестала работать

Внизу экрана тренажёра показывается состояние:

| Надпись | Что значит |
|---|---|
| Синхронизировано | всё в порядке |
| Нет связи с облаком | правила отклоняют запись — проверить, что `TEAM` не короче 20 символов |
| Только на этом компьютере | SDK не загрузился или игрок не выбран; данные пишутся локально и не потеряются |
