# Семейная команда: общая история, два профиля, взрослая лестница

**Дата:** 02.10.2026
**Проект:** тренажёр устного счёта «Устный счёт» (dana-schet)
**Участники:** Дана (4–5 класс) и папа

---

## Зачем

Сейчас тренажёр рассчитан на одного человека, и весь прогресс живёт в
`localStorage` одного браузера. Нужно три вещи:

1. Рейтинг и история не теряются и доступны с любого устройства.
2. Дана и папа — команда, которая поднимается вместе.
3. У папы задачи заметно тяжелее, иначе соревнование бессмысленно.

**Главное ограничение, заданное владельцем:** у Даны нет Claude, и привязки к
Claude быть не должно. Тренажёр обязан работать сам по себе.

---

## Принятые решения

| Вопрос | Решение | Почему |
|---|---|---|
| Где живёт | GitHub Pages | независимость от Claude; устанавливается как приложение, работает офлайн |
| Где хранится | Firebase Firestore | код уже написан под это API (см. ниже) |
| Рост команды | день засчитан, когда норму выполнили **оба** | взаимная ответственность, а не «вытянул один» |
| Совместное занятие | две минуты подряд с передачей хода | спокойнее эстафеты, каждый в своём темпе |
| Сложность папы | продолжение лестницы вверх + калибровка | уровень заранее неизвестен, пусть система найдёт |

### Почему именно Firestore

В текущем коде синхронизация уже написана под Firestore-подобный интерфейс:

```js
DB.doc('app/state').set(...)
db.collection('sessions').orderBy('ts','desc').limit(1000).get()
db.doc('app/state').onSnapshot(...)
```

Артефактная база Claude повторяет API Firestore, поэтому автор так и написал.
Переход на настоящий Firestore меняет только получение объекта `db` — вся
логика синхронизации, слияния и подписки остаётся.

Ключ Firebase в коде — норма, он не секрет. Доступ закрывается правилами на
стороне базы: писать может тот, кто знает ключ команды. Дана вводит его один
раз на своём ноутбуке.

## Режимы и профили

### Выбор профиля

При первом открытии на устройстве — экран «Кто ты?»: **Дана** или **Папа**.
Выбор запоминается на устройстве. Профиль папы закрывается существующим PIN,
чтобы Дана не могла сыграть за него и обрушить команду.

### Экран Даны

```
[ Заниматься вместе ]        [ Заниматься одной ]
```

**Вместе** — две минуты подряд на одном ноутбуке:

```
минута Даны (её уровень)
    ↓
экран передачи хода: «Теперь папа»
    ↓
минута папы (его уровень)
    ↓
общий итог на двоих
```

Результаты пишутся **каждому в свой профиль**, а день засчитывается обоим.

**Одной** — обычный заход. Её статистика пишется полностью, команда ждёт вклада
папы.

Папа со своего устройства делает свою минуту отдельно — день команды
закрывается задним числом, когда вторая половина подтянется.

---

## Правила команды

**Норма** — личная у каждого: сколько минутных заходов нужно сделать за день.
Задаётся отдельно для Даны и для папы в родительском разделе (сейчас это
общая настройка `perDay`, станет настройкой каждого игрока). По умолчанию
у обоих — пять заходов.

**Ступень команды** даётся за день, в который **оба** выполнили свою норму —
неважно, вместе за одним ноутбуком или порознь.

**Ступени не хранятся счётчиком, а пересчитываются из истории дней.** Это
защита по устройству, а не по везению: два устройства, синхронизируясь, не
смогут засчитать один день дважды.

**Смягчение, чтобы не наказывать ребёнка за отъезд родителя:**

- личный прогресс, монеты и достижения Даны начисляются **всегда**, за каждый
  её день, в одиночку или вместе;
- командная ступень **ждёт** папу и засчитывается задним числом, когда он
  наверстает.

Так её усилия не пропадают, а стимул «не подвести» остаётся у взрослого, а не
у ребёнка.

На экране у обоих — общая лестница команды и две полоски личного прогресса
рядом с ней.

---

## Данные

```
teams/<id команды>/
  state                 ступени, серия, история дней команды
  players/dana          уровни, факты, ошибки, монеты, достижения
  players/papa          то же самое, отдельно
  sessions/<id>         все заходы обоих, с разбором каждого примера
```

**Разделение записи:** каждый пишет только в свою ветку `players/<кто>`.
Столкновений не бывает по структуре.

**Общее состояние** (`state`) — производное: ступени и серия вычисляются из
дней обоих игроков, а не накапливаются независимо.

**Офлайн:** Firestore держит локальный кэш — Дана занимается без интернета,
записи досылаются при подключении. `localStorage` остаётся вторым носителем:
если облако недоступно совсем, ничего не теряется.

---

## Взрослая лестница

Нынешний потолок — 15-й уровень (уравнения, буквенные выражения). Для взрослого
это не предел, и упереться там не во что.

**Добавляем продолжение вверх:** трёхзначное умножение, деление с остатком,
дроби, проценты, квадраты двузначных.

**Калибровка при первом входе папы:** десяток примеров разной тяжести, после
которой система ставит его сразу на свой уровень — без прохождения таблицы
умножения на 2.

**Дальнейший рост по факту:** папа идёт вверх, пока не упрётся. Где встанет —
там лестницу и нарастим. Состав верхних уровней заранее не фиксируем: он
определяется тем, где реально кончится запас.

---

## Чего не делаем

- **Не делаем эстафету** с чередованием примеров в одной минуте — отклонено в
  пользу двух минут подряд.
- **Не делаем рост по отстающему** — обесценивает усилия того, кто старался.
- **Не делаем свой сервер** на Cloudflare — лишняя деталь для двух человек.
- **Не делаем Supabase** — пришлось бы переписать весь слой синхронизации без
  выигрыша.
- **Не фиксируем состав взрослых уровней заранее** — наращиваем по месту упора.

## Порядок работ

Объём больше одного подхода, поэтому делается слоями — каждый слой оставляет
рабочий тренажёр, которым уже можно пользоваться.

1. **Публикация.** Выложить нынешнюю версию на GitHub Pages, установить у Даны
   как приложение. Она начинает заниматься сразу, пока делается остальное.
2. **Облако.** Подключить Firestore вместо артефактной базы. Прогресс перестаёт
   быть привязанным к одному браузеру.
3. **Два профиля.** Выбор игрока на устройстве, PIN на профиле папы, раздельные
   данные и раздельная норма.
4. **Команда.** Общая лестница, правило «оба выполнили», зачёт задним числом.
5. **Совместный режим.** Две минуты подряд с передачей хода и общим итогом.
6. **Взрослая лестница.** Уровни выше 15-го и калибровка при первом входе папы.

Слой 1 даёт пользу в тот же день и не зависит от остальных. Слои 3–5 идут
строго по порядку: команда не имеет смысла без профилей, совместный режим — без
команды.

## Критерии готовности

1. Тренажёр открывается по ссылке GitHub Pages и устанавливается как приложение
   на ноутбуке Даны (иконка, отдельное окно, работа без интернета).
2. На устройстве выбирается профиль; профиль папы защищён PIN.
3. Дана проходит минуту одна — её прогресс и история сохраняются в облаке и
   видны с другого устройства.
4. Режим «вместе» проводит две минуты подряд и подводит общий итог; результаты
   попадают каждому в свой профиль.
5. День команды засчитывается только когда оба выполнили норму, и
   засчитывается задним числом, если второй наверстал позже.
6. Повторная синхронизация двух устройств не создаёт дублей ступеней.
7. Папа при первом входе проходит калибровку и получает уровень выше детского.
8. Отключение интернета не теряет результат: после восстановления связи данные
   доезжают.
